# 风堇 Codex 用量桌宠实施计划

## 1. 产品定义

交付由两个互补部分组成：

1. **Codex 原生 v2 宠物包**：遵循 Codex 固定的 8 列 × 11 行图集规范，包含 9 个标准动画状态和 16 个视线方向，可安装到 Codex 自定义宠物目录。
2. **Windows 独立悬浮桌宠**：复用同一角色设计，额外实现多待机、无聊、摸头、用量气泡、阈值事件和本地设置。需要自定义交互的功能以此运行时为准。

这样可以兼容 Codex 原生桌宠，同时不受原生固定动画行限制。

## 2. 角色与视觉方向

### 角色基准

- 角色：风堇 Q 版同人形象。
- 比例：大头、小身体、完整全身、紧凑直立轮廓，适合约 `192 × 208` 像素单元格。
- 轮廓参考：天选姬桌宠的桌面可读性和重心组织；不复制其具体轮廓、姿势或素材。
- 表现重点：面部在小尺寸下仍清楚；发型、主色、服装识别点保持稳定；避免过细配饰和漂浮特效。
- 素材背景：制作阶段使用单色键控背景，最终输出透明背景。

### 首轮需确认的主视觉

先生成一张完整全身、正面、自然站立的主参考图。只有在角色识别、比例、颜色和脸部通过人工确认后，才生成全部动画，避免后期整批返工。

推荐在生成前准备 1–3 张风堇官方立绘或用户认可的参考截图；只用作角色一致性参考，不直接裁切进成品。

## 3. 动画清单

### Codex 原生 v2 图集

最终图集固定为 `1536 × 2288`，单格 `192 × 208`，`spriteVersionNumber: 2`。

| 原生状态 | 设计表现 | 对应需求 |
| --- | --- | --- |
| `idle` | 呼吸、眨眼、轻微发丝摆动 | 基础待机 |
| `running-right` | 被拖动时向右移动 | 原生移动 |
| `running-left` | 被拖动时向左移动 | 原生移动 |
| `waving` | 召唤时抬手并转向用户 | 召唤/直视 |
| `jumping` | 轻微跃起或开心回应 | 正向反馈 |
| `failed` | 眼眶含泪、委屈哭泣 | 用量阈值/失败 |
| `waiting` | 眼睛发亮、微前倾等待 | 鼠标悬停/期待 |
| `running` | 专注思考或忙碌 | Codex 工作中 |
| `review` | 认真查看、轻歪头 | Codex 审阅中 |
| 16 directions | 眼睛先动，头颈与上身轻微跟随 | 看向鼠标/用户 |

原生图集不能增加自定义动画行。独立运行时将使用下面的扩展动画剪辑：

| 扩展剪辑 | 建议帧数 | 表现 |
| --- | ---: | --- |
| `direct` | 6 | 转向正面、眨眼并直视用户 |
| `idle-calm` | 6 | 呼吸与慢眨眼 |
| `idle-curious` | 6 | 轻歪头、视线短暂游移 |
| `idle-sleepy` | 6 | 眼皮变沉、轻微打盹 |
| `bored` | 8 | 轻叹气、鼓脸或托腮，不使用漂浮特效 |
| `expecting` | 6 | 眼睛发亮、身体微前倾 |
| `head-pat` | 8 | 闭眼开心、头部轻轻下沉再回弹 |
| `crying` | 8 | 含泪委屈；泪水保持连接在脸部轮廓内 |

## 4. 互动状态机

### 默认时间（均做成可配置项）

- 启动或手动召唤：`direct` 播放并保持约 8 秒。
- 鼠标离开或点击动画结束后：视为近期互动，继续 `direct` 约 12 秒。
- 无交互 20 秒：进入多个 `idle-*` 循环，按权重随机选择且避免连续重复。
- 无交互 10 分钟：进入 `bored`，首次进入时显示用量气泡。
- 鼠标进入桌宠命中区域：立即切换 `expecting`。
- 单击桌宠头部热区：播放一次 `head-pat`，同时显示用量气泡；结束后回到 `direct`。

### 状态优先级

从高到低：

1. 用量阈值哭泣事件
2. 点击摸头
3. 鼠标悬停期待
4. 启动、召唤或近期互动直视
5. 长时间无聊
6. 普通待机

高优先级动画结束后重新根据当前鼠标位置和最后互动时间计算状态，不直接写死下一个状态。

## 5. 用量显示与阈值规则

### 展示内容

气泡至少显示：

- 5 小时窗口剩余百分比和重置倒计时
- 每周窗口剩余百分比和重置时间
- 最近更新时间
- 数据不可用时的明确状态，而不是显示伪造的 `0%`

### 阈值事件

分别监控 5 小时与每周窗口。当任一窗口从高于阈值下降到该阈值或更低时，触发一次 `crying` 与用量气泡：

`80% → 60% → 40% → 20% → 1%`

实现规则：

- 使用“向下穿越”判定，例如 `63% → 58%` 只触发 `60%`。
- 若一次刷新跨过多个档位，只播放一次哭泣，气泡标出最低跨越档位，并把所有已跨档位记为已通知。
- 两个窗口独立保存已触发档位；同一刷新若二者同时跨档，合并成一个气泡。
- 根据每个窗口的 `resetAt` 识别新周期；重置后清空该窗口的已通知档位。
- 应用重启后从本地状态恢复，避免重复哭泣。
- 数据陈旧、读取失败或数值反向异常时不触发阈值事件。

### 数据来源策略

官方资料确认可以在 Codex 设置/用量页面查看余额和重置时间，也可以在活动中的 Codex CLI 使用 `/status`；目前已核实的公开资料未提供面向个人桌面应用的稳定结构化剩余用量 API。因此先实现数据适配接口，再通过可行性实验选定来源：

1. **首选**：本机可获得的官方结构化用量能力（若运行时可合法调用且无需复制凭据）。
2. **候选**：通过受控 PTY 运行 Codex CLI `/status` 并解析输出；必须检测 CLI 版本和格式变化。
3. **开发/降级**：读取本地 `usage-snapshot.json`，用于 UI 开发、演示和手工更新。
4. **最终降级**：显示“用量暂不可用”，并提供一键打开 Codex 用量页面；不抓取浏览器 Cookie，不静默爬取账户页面。

代码层使用统一的 `IUsageProvider`，UI 和阈值引擎不依赖具体来源。

## 6. 程序架构

```text
Pet.App
├─ OverlayWindow          # 透明、置顶、拖拽、缩放、屏幕边缘吸附
├─ AnimationController    # 帧播放、剪辑切换和不可打断区间
├─ InteractionController  # 悬停、头部热区、点击和召唤
├─ PetStateMachine        # 状态优先级与时间转换
├─ UsageService           # 轮询、缓存、陈旧判断
├─ ThresholdEngine        # 80/60/40/20/1 向下穿越事件
├─ SpeechBubble           # 用量文本、自动定位和屏幕边界避让
├─ SettingsService        # JSON 配置与状态持久化
└─ TrayController         # 召唤、隐藏、刷新、设置、退出
```

建议默认每 2 分钟刷新一次用量；用户主动点击时允许刷新，但设置最短请求间隔，避免频繁调用。

## 7. 分阶段实施

### 阶段 0：可行性与规格冻结

- 验证 Windows、Codex CLI 与本机可用的数据来源。
- 定义 `UsageSnapshot` 数据结构并用模拟数据覆盖全部阈值。
- 确认角色主参考图、桌宠显示尺寸、是否开机启动和气泡文案风格。
- 产出：技术探针结果、视觉简报、最终配置默认值。

状态：**已完成（2026-09-08）**。详见 `PHASE-0-REPORT.md`。

### 阶段 1：桌宠运行时骨架

- 创建 .NET 10 WPF 项目、透明窗口、托盘菜单和单实例机制。
- 使用临时占位图实现拖动、悬停、点击、召唤和气泡。
- 先写状态机与阈值单元测试，再接正式素材。
- 产出：可运行的占位版 `exe`。

### 阶段 2：主视觉与 Codex 标准动画

- 用 ImageGen 制作并确认风堇 Q 版主参考图。
- 按顺序生成 9 个标准动画行、四方向锚点和两行连续视线方向。
- 做逐行动画预览、透明度、轮廓、方向语义和一致性 QA。
- 产出：合规的 Codex v2 宠物包、联系表和预览 GIF。

### 阶段 3：扩展互动动画

- 在已确认的主视觉基础上生成 `direct`、三种待机、`bored`、`expecting`、`head-pat`、`crying`。
- 转换为统一尺寸、基线和透明背景的运行时动画资源。
- 产出：独立桌宠动画包及视觉验收表。

### 阶段 4：真实用量接入

- 实现并验证选定的 `IUsageProvider`。
- 增加缓存、超时、格式变化检测、重置识别和数据陈旧提示。
- 通过模拟序列验证全部阈值、跨多档、双窗口同时触发和重启恢复。

### 阶段 5：整合与发布

- 完成气泡避让、多屏/DPI、缩放、拖动吸附和托盘设置。
- 测试断网、Codex 未登录、CLI 缺失、休眠唤醒和跨周期重置。
- 发布自包含 Windows 单文件程序，并复制到 `08_Exports/codex-usage-pet`。
- 单独输出 Codex 原生宠物安装包及安装/卸载说明。

## 8. 宠物制作进度清单

按 `hatch-pet` 工作流维护以下四步，一次只将一个步骤标为进行中：

- [x] Getting 风堇 ready：已确定名称、描述、参考来源、风格和工作目录。
- [ ] Imagining 风堇's main look：生成并确认主参考形象。
- [ ] Picturing 风堇's poses：生成并验证标准动画与 16 个视线方向。
- [ ] Hatching 风堇：组装、视觉 QA、v2 验证、打包和安装。

## 9. 验收标准

- 启动、召唤、悬停、点击、普通待机和长时间无聊的状态转换符合规则。
- 至少三种待机循环可见且不会连续机械重复。
- 点击头部才触发摸头；透明空白区域不误触。
- 5 小时与每周窗口的五个阈值均只在向下穿越时触发一次，并在对应周期重置后恢复。
- 用量不可用时不误报 `0%`、不触发哭泣，也不暴露账号凭据。
- Codex 原生包通过 v2 图集结构、透明度、方向和动画 QA。
- 独立程序在常见 DPI 与多屏场景不裁切角色或气泡，空闲时资源占用合理。
- 最终交付包含运行、配置、安装、卸载和故障排查说明。

## 10. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| 个人用量没有稳定公开 API | 先做数据探针；适配器隔离；保留快照与打开用量页降级 |
| 角色多批次生成后外观漂移 | 先确认唯一主参考；所有动画以其为输入；逐行 QA，失败只重做对应行 |
| 原生 Codex 动画状态不足 | 原生包与独立悬浮运行时分开交付，共享设计而非共享状态约束 |
| 阈值反复触发 | 持久化周期 ID、上次百分比与已通知档位，使用向下穿越规则 |
| 透明窗口误挡鼠标 | 使用角色 alpha 命中测试；空白区域点击穿透；提供托盘紧急隐藏 |
| 同人角色与参考产品的知识产权边界 | 仅个人使用；不提取、复制或分发原始资产与商标元素 |
